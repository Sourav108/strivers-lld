## 1. Problem, Restated

Find all unique triplets $[nums[i], nums[j], nums[k]]$ such that $i \neq j \neq k$ and $nums[i] + nums[j] + nums[k] == 0$.

- **Input**: Vector of integers `nums`.
- **Output**: Result as specified by problem requirements.
- **Key Constraints**: $n$ up to $10^5$, elements can be negative/positive, time limit 1.0s.

---

## 2. Intuition & Pattern

Sort + Two Pointers. Fix $nums[i]$, then find pair sum $-nums[i]$ while skipping duplicates.

- **Underlying Pattern**: Array Manipulation / Mathematical Invariants / Pointers.
- **The "Aha!" Moment**: Recognizing how to avoid redundant work by storing running state or leveraging sorting invariants.

---

## 3. Approach 1 — Brute Force

### Idea
Check all possibilities exhaustively using nested loops.

### C++17 Code
```cpp
#include <vector>
#include <algorithm>
#include <climits>
#include <set>
#include <unordered_map>
using namespace std;

vector<vector<int>> threeSumBrute(vector<int>& nums) {
    set<vector<int>> st; int n = nums.size();
    for (int i=0; i<n; i++)
        for (int j=i+1; j<n; j++)
            for (int k=j+1; k<n; k++)
                if (nums[i]+nums[j]+nums[k] == 0) {
                    vector<int> t = {nums[i], nums[j], nums[k]};
                    sort(t.begin(), t.end()); st.insert(t);
                }
    return vector<vector<int>>(st.begin(), st.end());
}
```

### Complexity Derivation
- **Time Complexity**: O(n^3 log(triplets))
- **Space Complexity**: O(triplets)
- **Why it's not good enough**: For $n = 10^5$, polynomial time $\mathcal{O}(n^2)$ takes $\approx 10^{10}$ operations and triggers Time Limit Exceeded (TLE).

---

## 4. Approach 2 — Better

### Idea
Two Loops + Hash Set Lookup: Loop $i$ and $j$, look for $-(nums[i] + nums[j])$ in a hash set of already visited elements in the inner loop, and insert sorted triplets into `std::set` to deduplicate.

### C++17 Code
```cpp
#include <vector>
#include <unordered_set>
#include <set>
#include <algorithm>
using namespace std;

vector<vector<int>> threeSumBetter(vector<int>& nums) {
    set<vector<int>> uniqueTriplets;
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        unordered_set<int> seen;
        for (int j = i + 1; j < n; j++) {
            int third = -(nums[i] + nums[j]);
            if (seen.count(third)) {
                vector<int> triplet = {nums[i], nums[j], third};
                sort(triplet.begin(), triplet.end());
                uniqueTriplets.insert(triplet);
            }
            seen.insert(nums[j]);
        }
    }
    return vector<vector<int>>(uniqueTriplets.begin(), uniqueTriplets.end());
}
```

### Complexity Derivation
- **Time Complexity**: $\mathcal{O}(n^2 \log(\text{triplets}))$ — hash set lookups and tree set insertions.
- **Space Complexity**: $\mathcal{O}(n + \text{triplets})$ — hash set and tree set memory.
- **Why it's still not optimal**: High constant factors and tree set memory overhead; sorting + two-pointer removes extra space and log factors.

---

## 5. Approach 3 — Optimal

### Idea
Production-quality single-pass or $\mathcal{O}(n \log n)$ divide-and-conquer implementation.

### C++17 Code
```cpp
#include <vector>
#include <algorithm>
#include <climits>
#include <unordered_map>
#include <unordered_set>
using namespace std;

vector<vector<int>> threeSumOptimal(vector<int>& nums) {
    vector<vector<int>> res;
    sort(nums.begin(), nums.end());
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;
        int left = i + 1, right = n - 1;
        while (left < right) {
            int sum = nums[i] + nums[left] + nums[right];
            if (sum == 0) {
                res.push_back({nums[i], nums[left], nums[right]});
                left++; right--;
                while (left < right && nums[left] == nums[left - 1]) left++;
                while (left < right && nums[right] == nums[right + 1]) right--;
            } else if (sum < 0) left++;
            else right--;
        }
    }
    return res;
}
```

### Complexity Derivation
- **Time Complexity**: O(n^2)
- **Space Complexity**: O(1)
- **Why this is optimal**: Matches the theoretical information lower bound $\Omega(n)$ for unsorted array inspection.

## 8. Follow-Up Questions (Interview Style)

- **Q1: Why is sorting the array acceptable when aiming for O(n^2) total time?**  
  **A**: Sorting takes $\mathcal{O}(n \log n)$, while the nested two-pointer scan takes $\mathcal{O}(n^2)$. Since $\mathcal{O}(n \log n)$ is asymptotically smaller than $\mathcal{O}(n^2)$, sorting adds zero overhead to the overall complexity.

- **Q2: How do we strictly prevent duplicate triplets without using `std::set`?**  
  **A**: 1) Skip duplicate outer elements: `if (i > 0 && nums[i] == nums[i-1]) continue;`. 2) After finding a triplet, advance pointers past duplicate values: `while (left < right && nums[left] == nums[left-1]) left++; while (left < right && nums[right] == nums[right+1]) right--;`.

- **Q3: How to solve 3Sum Closest (finding triplet whose sum is closest to target)?**  
  **A**: Sort array, run Two Pointers, compute `diff = abs(target - sum)`. If `diff < minDiff`, update `closestSum = sum`. If `sum < target` `left++`, else `right--` in $\mathcal{O}(n^2)$ time and $\mathcal{O}(1)$ space.

- **Q4: What is the 3SUM Conjecture in computational complexity?**  
  **A**: The 3SUM Conjecture states that no algorithm can solve the 3SUM problem in $\mathcal{O}(n^{2-\epsilon})$ time for any $\epsilon > 0$. It forms the foundation for lower bounds in computational geometry.

- **Q5: What if the array is huge and stored across distributed nodes?**  
  **A**: Partition data into hash ranges, replicate boundary candidate buckets across nodes, and run parallel two-pointer merges.
